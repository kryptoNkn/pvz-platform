# П25. Спецификация API отчета загрузки по часам

## 1. Назначение

Эндпоинт возвращает агрегированные данные по операциям `in`, `out`, `return`, сгруппированные по часу суток.  
Отчет используется для построения графиков загрузки и анализа пиковых часов.

## 2. Endpoint

- **Метод:** `GET`
- **Путь:** `/api/v1/stats/workload-by-hour`

Маршрут зарегистрирован в backend как часть scope `/api/v1`.

## 3. Доступ

- Требуется аутентификация через JWT.
- Поддерживаются оба варианта передачи токена:
  - заголовок `Authorization: Bearer <token>`;
  - cookie `access_token`.
- Ограничения по роли нет: доступ есть у любого аутентифицированного пользователя.

## 4. Query-параметры

| Параметр | Тип | Обязательный | Формат | Описание |
| --- | --- | --- | --- | --- |
| `pvz_id` | `string` | нет | UUID | Фильтр по конкретному ПВЗ. Если не передан, отчет строится по всем ПВЗ. |
| `date_from` | `string` | нет | RFC3339 / ISO-8601 | Нижняя граница периода включительно. |
| `date_to` | `string` | нет | RFC3339 / ISO-8601 | Верхняя граница периода включительно. |

### Примеры формата дат

- `2026-05-01T00:00:00Z`
- `2026-05-27T12:30:00+03:00`

## 5. Правила фильтрации

1. Если `pvz_id` не задан, берутся операции по всем ПВЗ.
2. Если `date_from` не задан, нижняя граница не применяется.
3. Если `date_to` не задан, верхняя граница не применяется.
4. Группировка идет по часу в **UTC**.
5. Часы без операций в ответ не попадают.
6. Если в выбранном интервале нет данных, ответ будет пустым массивом `[]`.

## 6. Формат ответа

Ответ всегда имеет формат массива объектов.

### Поля элемента массива

| Поле | Тип | Описание |
| --- | --- | --- |
| `hour` | `integer` | Час суток от `0` до `23` в UTC. |
| `acceptance` | `integer` | Сумма `quantity` по операциям `op_type = "in"`. |
| `delivery` | `integer` | Сумма `quantity` по операциям `op_type = "out"`. |
| `returns` | `integer` | Сумма `quantity` по операциям `op_type = "return"`. |
| `total` | `integer` | Общая сумма `quantity` по всем операциям в этом часу. |
| `ops_count` | `integer` | Количество строк операций, попавших в группу. |

## 7. Пример запроса

```http
GET /api/v1/stats/workload-by-hour?pvz_id=11111111-1111-1111-1111-111111111111&date_from=2026-05-01T00:00:00Z&date_to=2026-05-07T23:59:59Z
Authorization: Bearer <access_token>
```

## 8. Пример ответа

```json
[
  {
    "hour": 9,
    "acceptance": 124,
    "delivery": 88,
    "returns": 7,
    "total": 219,
    "ops_count": 42
  },
  {
    "hour": 10,
    "acceptance": 143,
    "delivery": 97,
    "returns": 11,
    "total": 251,
    "ops_count": 49
  }
]
```

## 9. Коды ответов

| Код | Сценарий |
| --- | --- |
| `200 OK` | Отчет успешно сформирован. |
| `401 Unauthorized` | Не передан или невалиден JWT. |
| `500 Internal Server Error` | Ошибка базы данных или выполнения запроса. |

## 10. Технические замечания

1. В текущей реализации невалидные значения `date_from` и `date_to` не вызывают ошибку `400`, а просто не участвуют в фильтрации.
2. Отчет агрегирует данные только по часу суток, а не по дате.  
   Если период охватывает несколько дней, все записи с одинаковым часом будут объединены в одну строку.
3. Если нужен сводный KPI без фильтров, смежный endpoint — `GET /api/v1/stats`. Он не принимает query-параметров.
