# П14. Анализ процессов

## 1. Макропроцесс: Жизненный цикл посылки
Этот процесс описывает путь материального объекта через систему. Каждому этапу соответствует программный триггер в коде на Rust.

1.  **Приемка (Inbound):**
    * **Вход:** Посылка от курьера/магистрали.
    * **Действие:** Сканирование/регистрация в системе.
    * **Результат:** Событие `ItemReceived`, посылка получает статус «На складе».
2.  **Сортировка и Размещение:**
    * **Действие:** Определение ячейки хранения (на основе внутренних правил ПВЗ).
    * **Системный след:** Обновление метаданных объекта в БД.
3.  **Хранение:**
    * **Процесс:** Ожидание клиента.
    * **Контроль:** Система отслеживает срок хранения. При превышении — команда на возврат.
4.  **Выдача (Outbound):**
    * **Вход:** Визит клиента, проверка ID.
    * **Действие:** Смена статуса на «Выдано».
    * **Результат:** Событие `ItemIssued`, списание с баланса точки.

## 2. Аналитический процесс: Мониторинг нагрузки
Это ключевой интеллектуальный процесс системы, который работает в фоновом режиме.

* **Сбор данных:** Система агрегирует количество событий `In/Out/Return` за последний час.
* **Сравнение с лимитом:** Параметр `ops_per_hour` (установленный Владельцем) выступает как эталон.
* **Вычисление Load Factor:** $$LoadFactor = \frac{CurrentOperations}{CapacityLimit} \times 100$$
* **Детекция аномалий:** Если результат $> 100\%$, срабатывает **Overload Policy**.

## 3. Управленческий процесс: Реагирование
Как данные превращаются в действия бизнеса.

| Проблема | Индикатор в системе | Управленческое решение |
| :--- | :--- | :--- |
| **Очереди в ПВЗ** | Постоянный статус "Overload" в часы пик | Нанять второго оператора или открыть второе окно выдачи. |
| **Ошибки сотрудников** | Рост записей в «Журнале ошибок» | Проведение инструктажа по работе с интерфейсом. |
| **Низкая эффективность** | Загрузка ПВЗ < 20% в течение месяца | Перенос точки в более проходное место или сокращение штата. |

## 4. Технологический процесс (CI/CD)
Процесс обеспечения качества продукта через инфраструктуру GitVerse.

1.  **Разработка:** Написание кода (Rust/React) -> Push в репозиторий.
2.  **Верификация:** Автоматический запуск `cargo test` и `npm run dev`.
3.  **Сборка:** Создание Docker-образа при успешном прохождении тестов.
4.  **Деплой:** Обновление контейнера на сервере мониторинга.
