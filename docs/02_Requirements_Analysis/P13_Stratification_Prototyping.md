# П13. Стратификация и прототипирование

## 1. Стратификация системы (Слои архитектуры)
Система спроектирована по принципу «Чистой архитектуры», что позволяет изолировать технический стек (Rust/React) от ключевых бизнес-правил.

### 1.1. Слой представления (Presentation Layer)
- **Frontend (React + TS):** Отвечает за визуализацию данных, управление состоянием интерфейса и валидацию форм на стороне клиента.
- **API Handlers (Actix Web):** Эндпоинты на стороне Backend, которые принимают HTTP-запросы и возвращают JSON-ответы.

### 1.2. Доменный слой (Domain/Business Layer)
- **Сервисы:** Реализация алгоритмов «Расчет нагрузки» и «Детекция перегрузок».
- **Сущности (Entities):** Структуры данных Rust (Pvz, Operation, User), описывающие основные объекты системы.
- **Правила:** Логика проверки возможности выдачи товара или изменения графика работы.

### 1.3. Слой данных и инфраструктуры (Data/Infrastructure Layer)
- **Repository:** Слой взаимодействия с базой данных через **SQLx**.
- **Database (PostgreSQL):** Физическое хранение логов операций и справочников.
- **Middleware:** Слой безопасности, отвечающий за проверку JWT-токенов и прав доступа.

## 2. Прототипирование

### 2.1. Концептуальное прототипирование (Figma)
Перед написанием кода создаются визуальные прототипы, ориентированные на конкретные роли:
- **Дашборд Владельца:** Фокус на визуализации KPI (всего ПВЗ, средняя загрузка по сети).
- **Операционный интерфейс:** Упрощенные формы ввода для быстрой фиксации приемки и выдачи товара.
- **Аналитическая таблица:** Интерактивный список с цветовой индикацией «overload-статусов» (красная подсветка при перегрузке).

### 2.2. Функциональное прототипирование (MVP)
Прототип реализуется в виде минимально жизнеспособного продукта со следующими особенностями:
- **Data Engine:** На этапе прототипа используются валидированные синтетические данные для демонстрации работы графиков.
- **Инфраструктура:** Развертывание в Docker-контейнерах через **GitVerse Actions** для быстрой проверки гипотез.

## 3. Взаимодействие слоев
1. **Frontend** инициирует событие (например, запрос отчета).
2. **Middleware** проверяет политику доступа (RBAC).
3. **Domain Layer** выполняет расчет на основе данных из **Repository**.
4. Результат возвращается в **Presentation Layer** для отрисовки графиков.
