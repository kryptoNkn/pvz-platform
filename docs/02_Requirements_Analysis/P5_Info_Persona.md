# П5. Ознакомление с поиском информации и персоной

## 1. Поиск и фильтрация информации
Система построена на оперативной обработке данных, где поиск является ключевым инструментом для принятия решений. 

### 1.1. Механизмы поиска
* **Поиск по атрибутам:** Быстрый поиск ПВЗ по адресу, уникальному идентификатору (ID) или названию.
* **Фильтрация по состоянию:** Возможность сегментировать пункты выдачи по статусам загрузки («Все хорошо», «Перегрузка»).
* **Временные срезы:** Фильтрация операций и аналитики по датам, часам и дням недели для выявления «часов пик».
* **Типизация данных:** Поиск конкретных транзакций по типу: Приемка (`in`), Выдача (`out`), Возврат (`return`).

### 1.2. Техническая реализация поиска
* **Backend:** Выполнение асинхронных запросов через **SQLx** к PostgreSQL с использованием индексов по `pvz_id` и `timestamp`.
* **Frontend:** Реализация мгновенной фильтрации на стороне клиента (React) для улучшения UX мониторинга.

## 2. Персоны (User Personas)

### 2.1. Оператор ПВЗ (Линейный персонал)
* **Цель:** Быстро фиксировать движение товара и не допускать очередей.
* **Потребности:** Простой интерфейс «в одну кнопку», визуальный индикатор текущей нагрузки на его точке.
* **Ключевой сценарий:** Приемка большой партии товара утром → Проверка статуса «Загрузка» → Выдача товаров клиентам вечером.

### 2.2. Владелец сети (Бизнес-аналитик)
* **Цель:** Контроль рентабельности и масштабирование.
* **Потребности:** Глобальный дашборд с KPI по всей сети, экспорт отчетов в CSV для финансового отдела.
* **Ключевой сценарий:** Просмотр аналитики за месяц → Выявление ПВЗ со стабильной перегрузкой в 100% → Принятие решения об открытии второй точки в этом районе.

### 2.3. Администратор системы (Технический специалист)
* **Цель:** Обеспечение аптайма и чистоты данных.
* **Потребности:** Доступ к системным логам, управление правами доступа (RBAC), журнал ошибок.
* **Ключевой сценарий:** Получение уведомления о некорректных данных → Переход в «Журнал ошибок» → Корректировка справочника НСИ.

## 3. Карта взаимодействия (Persona-to-Data)
1. **Оператор** генерирует данные (события операций).
2. **Система** обрабатывает их (расчетный модуль).
3. **Владелец** потребляет результат (аналитические отчеты).
4. **Администратор** контролирует процесс (технический аудит).
