# П19. Построение начальной ER‑диаграммы

## 1. Описание сущностей (Entities)

### 1.1. Пользователь (User)
- **ID** (Primary Key): Уникальный идентификатор.
- **Username**: Логин для входа.
- **Password_Hash**: Хеш пароля (безопасность).
- **Role**: Роль пользователя (Owner, Admin, Operator).

### 1.2. ПВЗ (Point of Presence)
- **ID** (Primary Key): Уникальный идентификатор точки.
- **Address**: Физический адрес.
- **Capacity_Limit**: Максимальное количество операций в час (ops_per_hour).
- **Owner_ID** (Foreign Key): Ссылка на пользователя с ролью Owner.

### 1.3. Операция (Operation)
- **ID** (Primary Key): Уникальный идентификатор транзакции.
- **Type**: Тип (Reception, Issue, Return).
- **Timestamp**: Точное время проведения операции.
- **Pvz_ID** (Foreign Key): Ссылка на ПВЗ, где совершена операция.
- **Operator_ID** (Foreign Key): Ссылка на пользователя, совершившего действие.

### 1.4. График работы (Schedule)
- **ID** (Primary Key): Уникальный идентификатор.
- **Pvz_ID** (Foreign Key): Ссылка на ПВЗ.
- **Day_of_Week**: День недели.
- **Open_Time / Close_Time**: Время работы.

## 2. Связи (Relationships)

1. **User — ПВЗ (1:N)**: Один Владелец может управлять несколькими ПВЗ.
2. **ПВЗ — Операция (1:N)**: В одном ПВЗ совершается множество операций.
3. **User — Операция (1:N)**: Один Оператор может совершить множество операций.
4. **ПВЗ — График (1:N)**: Для одного ПВЗ задается расписание на разные дни недели.

## 3. Логическая схема данных

```text
[User] 1 ---- <Управляет> ---- N [Pvz]
  |                               |
  |                               |
  1                            <Имеет>
  |                               |
<Совершает>                       |
  |                               1
  |                               |
  N [Operation] N ---- <В рамках> -
```

## 4. Инварианты и ограничения
- Операция не может существовать без привязки к ПВЗ и Оператору.
- Пропускная способность ПВЗ должна быть больше нуля.
- Каждая запись в журнале операций неизменяема (Immutable) для обеспечения аудита.
