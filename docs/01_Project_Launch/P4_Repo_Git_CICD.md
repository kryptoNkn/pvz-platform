# П4. Самостоятельная настройка репозитория с Git и CI/CD
**Ссылка:** https://gitverse.ru/kryptonkn/pvz-platform.  
### 1. Подготовка и инициализация репозитория
* **Создание рабочего пространства:** Регистрация организации и основного репозитория в экосистеме GitVerse.
* **Локальная настройка:** Инициализация Git в корне проекта (`git init`), создание файла `.gitignore` (отдельно для Rust-артефактов, папок `node_modules` и конфигурационных файлов БД).
* **Связывание сред:** Настройка удаленного репозитория (Remote) и проверка прав доступа для всех участников команды (TL, Backend, Frontend).

### 2. Организация совместной работы (Git Flow)
* **Настройка ветвления:** Определение структуры веток (`main` для релизов, `develop` для разработки и `feature/*` для отдельных задач).
* **Правила слияния (Branch Protection):** Установка запрета на прямые пуши в `main` и настройка обязательного Code Review перед слиянием веток.
* **Контроль версий документации:** Настройка папки `/docs` для хранения ТЗ и схем, соответствующих ГОСТ 2.105-95.

### 3. Конфигурация CI (Continuous Integration)
* **Настройка GitVerse Actions:** Создание YAML-файлов для автоматизации проверок при каждом Pull Request.
* **Pipeline для Backend (Rust):**
    * Автоматическая сборка проекта (`cargo build`).
    * Запуск тестов (`cargo test`) для проверки расчетных модулей.
    * Проверка кода линтером (`cargo clippy`) на соответствие стандартам.
* **Pipeline для Frontend (React/TS):**
    * Установка зависимостей и сборка бандла.
    * Проверка типизации TypeScript.
    * Линтинг кода (ESLint/Prettier).

### 4. Конфигурация CD (Continuous Deployment) и Docker
* **Контейнеризация:** Написание `Dockerfile` с использованием **Multi-stage build**, чтобы минимизировать размер итогового артефакта.
* **Управление секретами:** Настройка переменных окружения (Secrets) в GitVerse для безопасного хранения доступов к PostgreSQL и JWT-ключей.
* **Автоматизация деплоя:** Настройка пайплайна для автоматической сборки Docker-образа и его отправки на целевой сервер при слиянии кода в основную ветку.

## **Структура веток:**
### 1. Корень проекта (Root)
- `backend/` — Серверная часть приложения (Rust).
- `frontend/` — Клиентская часть приложения (React + TypeScript).
- `docs/` — Проектная документация.
- `docker-compose.yml` — Конфигурация для запуска всей системы в контейнерах.
- `.gitignore` — Исключения для Git (отдельно для Rust и Node.js).
- `README.md` — Описание проекта и инструкции по запуску.

#### 2. Backend (Rust + Actix Web)
- `src/`
    - `main.rs` — Точка входа в приложение.
    - `api/` — Обработчики HTTP-запросов (Handlers) и роутинг.
    - `services/` — Бизнес-логика (расчет загрузки, детекция перегрузок).
    - `models/` — Описание структур данных (Structs).
    - `repository/` — Взаимодействие с базой данных (SQLx/PostgreSQL).
    - `middleware/` — Проверка JWT-токенов и прав доступа (RBAC).
- `migrations/` — SQL-скрипты для миграции базы данных.
- `Cargo.toml` — Конфигурация зависимостей Rust.
- `Dockerfile` — Сборка образа (Multi-stage build).

#### 3. Frontend (React + TS + Vite)
- `src/`
    - `api/` — Настройка Axios и Interceptors для связи с бэкендом.
    - `components/` — UI-kit и общие компоненты (Shared).
    - `pages/` — Основные экраны (Dashboard, Login, PVZ List, Error Log).
    - `assets/` — Стили (SCSS), изображения и шрифты.
    - `hooks/` — Пользовательские хуки для управления состоянием.
    - `context/` — Глобальный стейт (авторизация, данные пользователя).
- `public/` — Статические файлы.
- `package.json` — Зависимости Node.js.
- `vite.config.ts` — Конфигурация сборщика Vite.

#### 4. Инфраструктура (GitVerse)
- `.github/workflows/` (или `.gitverse/workflows/`)
    - `backend-ci.yml` — Сборка, cargo test, cargo clippy.
    - `frontend-ci.yml` — Сборка, проверка типов TS, линтинг.
    - `deploy.yml` — Автоматический деплой Docker-контейнеров.
